## 0. M1 要回答的四个问题

M1 不是“缩水版正式游戏”，而是一次带验收门槛的技术冒险：

1. **身体手感**：在手机上，左摇杆 + 三键能否稳定完成移动、可变跳、土狼时间、跳跃缓冲、下压砸地？
2. **瞄准手感**：8 向射击 + 自动瞄准 + 情境小刀是否比“加右摇杆/加近战键”更适合本作？
3. **破坏玩法**：同一张灰盒关里，能否稳定复现“炸穿地面开路”和“炸塌平台埋敌人”，并让链爆有节奏而不是随机卡顿？
4. **性能路径**：在目标中端真机、1080p、60 Hz 下，200 同屏碎片 + 坍塌 + 链爆有没有可行的实现路径？如果达不到，真实上限是多少？

**M1 通过才做 M2。没通过就改方案，不用“多画几个角色”掩盖核心风险。**

### 0.1 追加验收要求（已批准）

1. **P5 不计门槛**：200 个全 Rigidbody2D 照做并写入性能报告，作为 M3 优化余量；M1 Go/No-Go 仍只看 P4 的三级预算场景。
2. **小刀零误触**：自动近战不消费射击/手雷输入；只要 Fire/Grenade 任一按住或刚按下，就禁止自动出刀。敌人进入 1.15 格半径必须有世界环提示 + tick 音效，真正出刀带 2 帧 hitstop。
3. **Day 3 晚**必须有可安装的 APK（半成品可接受），用于真机摸跳跃、移动惯性和 8 向辅助力度；**Day 6**必须有性能趋势预览（不要求当时达标），不能把崩帧留到最后一天才说。
4. **强制坍塌教学**：装甲目标只能被“炸塌平台”压死；压死反馈的顿帧、震屏、敌人被埋都必须进 P0。
5. **CSV 可调性**：每张表附一句整体说明；每一行都有 `tune_up` / `tune_down` 的体感描述，不依赖代码。
6. **真机**：红米 Note 12（或同级、1080p/60Hz/Android 13）。允许云真机跑首轮趋势，但最终 Go/No-Go 必须在指定物理真机复测。
7. **数据红线**：性能 CSV 只来自真实运行；宁可 No-Go，不允许编数。
8. **范围**：只做 M1，不提前做 M2 的多角色/多关内容。

## 2. M1 测试关设计

### 2.1 路线

```text
出生
  ↓
A 区：移动 + 8 向瞄准靶场（跳台、窄沟、低矮掩体）
  ↓
B 区：薄地板 + 油桶/弹药箱（炸穿地面，进入地下通道）
  ↓
地下通道：巡逻假人 + 可打裂的薄墙
  ↓
C 区：高台坍塌陷阱（两根可破坏支柱，下方假人）
  ↓
D 区：出口 + 压力测试调试台（不参与正式路线）
```

- 首次试玩目标 60~90 秒；设 2 个检查点（A 区后、B 区地下入口），减少挫败。
- 灰盒视觉：泥土=棕、混凝土=深灰、结构支撑=黄黑条纹、油桶=红、弹药箱=橙、假人=白。所有素材由项目内程序色块/自绘灰盒图生成，不使用外部素材。

### 2.2 A 区：把身体和瞄准拆开测

- 3 级高度平台，验证跳跃高度、可变跳、落地缓冲；一段 1 格宽窄沟（不应靠运气过）。
- 8 向靶：在玩家四周固定布置 8 个木靶，其中 2 个在薄墙后，用于验证：
  - 摇杆空置时自动选择最近可视线目标；
  - 推摇杆时优先所选扇区；
  - 不会隔墙锁定；
  - 无目标时弹道严格沿 8 向中心；有目标时只在当前 45° 扇区内修正，不跨扇区。
- 自动瞄准指示器必须可见但不遮挡：目标头顶小括号 + 角色周围极简 8 向扇区浅色提示。

### 2.3 B 区：“炸穿地面开路”

剖面示意：

```text
         玩家 / 敌人
       ┌─────────────┐
       │ 薄地板 ×3    │  ← 手雷、油桶串爆可挖开
       ├─────────────┤
       │ 地下通道      │  ← 攻击后可通过、可掉敌
       ├─────────────┤
       │ 实心混凝土    │
       └─────────────┘
```

- 玩家在薄地板上放下/投掷手雷，或引爆旁边油桶，打通 3 格宽缺口。
- 坍塌/掉落碎片必须给下方通道留出可通行空间，不能把出口堵死。
- 测试：手雷、枪械、油桶链爆三种路径都能打通；玩家掉入后可以继续走完。
- 在通道内放置 2 个油桶 + 1 个弹药箱，测试链爆顺序和音画节奏。

### 2.4 C 区：“炸塌平台埋敌人”

剖面示意：

```text
       ██████████████  高台（可站立，非玩家解谜必需）
       └──支柱 1──支柱 2──┘
               ↓
            假人敌人
```

- 高台与两根黄黑支撑柱连通；两根都失去后，0.15~0.25 s 抖动/裂纹预警，然后平台整体坠落。
- 平台下方是**装甲目标**：普通子弹/爆炸不造成伤害，只会火花提示；唯一击杀路径是被坍塌平台压中。
- 出口闸门在装甲目标死亡前保持关闭，形成强制教学；不允许绕过。
- 压死必须同时产生：3 帧 hitstop、S3 震屏、敌人扁平埋压残影、碎屑/尘土、音效；坍塌块在 1.1 s 后清掉，避免挡路。
- 测试：
  - 只断一根支柱时平台不塌；
  - 两根断掉后必塌；
  - 同一平台不会重复生成多个坍塌体；
  - 装甲目标被平台压死、闸门开启、敌人被埋、反馈齐全；
  - 玩家站在旁边不会被莫名伤害；如果被砸中，伤害和无敌帧可读。
- M1 只做这一种“高台+支柱”结构；M2 再复用/泛化到不同关卡。禁止在 M1 做全图复杂结构力学。

### 2.5 压力测试台

- 开发专用，放在 D 区或通过调试手势呼出。
- 一键：
  - 生成 200 个可见碎片；
  - 同时保留 12 个全物理坍塌块；
  - 3 个油桶连续引爆；
  - 记录 10 秒帧时间与活跃对象数；
  - 切换“200 个全 Rigidbody2D”实验，记录真实上限。
- 压力测试的生成点、相机位置固定，保证每次测量可比较。
- 测试结果写入 CSV：时间戳、设备、构建类型、场景、平均 FPS、1%/0.1% low、最大帧、碎片数、全刚体数、GC Alloc。

## 3. 操作与镜头验收细项

### 3.1 触控

- 左摇杆固定左下安全区，死区 0.18；支持任意方向、多指操作。
- 右三键：射击最大；跳跃紧邻；手雷稍上移。触摸热区大于视觉 15~25%。
- 双拇指同时移动+射击 60 秒，不出现断触、粘键、按钮互相抢 pointerId。
- 手指从跳跃滑到射击时，不得丢事件；同时按住射击和手雷时，两者都生效。
- 切后台再回来，触摸状态归零，不遗留按住状态。
- 按钮按下与画面反馈 ≤ 2 帧（代码层统计；设备显示延迟不计入，但录屏观察应同步）。

### 3.2 8 向与自动瞄准

- 输入/枪口强制量化到 8 向；无目标时肉眼检查弹道严格沿中心；有目标时只允许在所选 45° 扇区内修正，不出现跨扇区拐弯。
- 自动瞄准选中的目标必须有视觉标记；不能“不知道在打谁”。
- 视线阻挡测试：两堵薄墙后各放一个靶，自动瞄准不能在墙后锁敌；墙被炸开后重新可选。
- 目标切换迟滞 0.12 s：两个等距敌人并排，不出现每帧来回切换。
- 弹道总宽 2 px（半宽 1 px）；目标中心与 45° 扇区有偏差时仍能命中，但不允许隔空大角度拐弯。
- 自动瞄准不是自动开火：不按射击键绝不开枪。
- 手雷是抛物线投掷，不吸附目标；按当前 8 向意图抛出，靠落点/反弹拆地形。

### 3.3 自动近战（按追加要求整改）

- 1.15 格内有普通敌人时显示世界环形触发半径，并播放一次 tick 音效。
- 自动近战不消费 Fire/Grenade 输入；出刀是额外反应，不替代射击/投雷。
- **只要 FireHeld / FirePressed / GrenadeHeld / GrenadePressed 任一成立，就禁止自动出刀**；近战函数内还有二次断言，防止误触发回归。
- 出刀本身有白色刀光、音效和 2 帧 hitstop，满足“轻微顿帧或音效”的可见反馈。
- 1.35 格外不得误触；装甲目标不参与自动近战，避免无效刀光。
- 不允许通过“近距离优先但延迟开枪”这类会改变射击意图的方案绕过；三键方案不得加第四键。

### 3.4 下压跳

- 空中按住下 + 跳跃 → 下压；落地有冲击、震屏、粒子、范围伤害。
- 地面上下 + 跳跃不触发下压，不做“蹲”状态。
- 下压不能穿过完整混凝土；能砸裂最薄弱的泥土地板（验证地形材质差异）。
- 下压落地后 0.1 s 内不能再跳，避免连跳取消冲击。

### 3.5 镜头与像素

- 1080p 16:9 基准机：世界画面显示完整 480×270 安全区，无拉伸、无滤波模糊。
- 更宽手机：横向多看到场景，但所有关键路径/敌人/出口在 480×270 安全区内。
- 相机跟随有 lookahead 和死区；移动时不抖，急停不甩。
- 震屏幅度按基础像素取整；普通击杀与爆炸震屏能明显区分，Boss 档只在调试触发时验证。
- 世界 Sprite 和相机像素吸附；UI 在原生分辨率，按钮和文字清晰。
- 屏幕安全区：刘海、挖孔、圆角不遮挡摇杆/按钮/HUD。

## 5. 关键技术实现顺序

1. **先呈现，后玩法**
   - 先打通 480×270 → 整数放大 → 原生 UI；否则所有手感观察都建立在错误画面上。
2. **先输入，后角色**
   - TouchRouter 的多指、pointer owner、按钮按下/抬起/取消先正确，再接移动；避免后面把输入 bug 误判成手感问题。
3. **先地形网格，后特效**
   - 网格和碰撞先正确，再做碎片；否则视觉会掩盖穿模和卡位。
4. **先单次爆炸，后链爆**
   - 单爆无重复、无溢出，再开链爆队列和上限。
5. **先坍塌脚本化，后泛化**
   - M1 的支撑图只需支持测试关的一座桥/一块平台；通过后再考虑 M2 多结构通用。
6. **先性能面板，后调参**
   - D1 就把帧时间/碎片/GC 计数放上屏；不要靠感觉调参。
7. **先真机，后收尾**
   - 每天结束前至少跑一次真机，不把问题攒到 D6。

## 7. 性能验证协议

### 7.1 设备与环境

- 基线机：**红米 Note 12（或同级天玑/骁龙中端、1080p、60 Hz、Android 13）**；M1 不接受只有 PC/Editor 数据。
- 允许先用云真机跑首轮趋势并记录设备信息；但 Go/No-Go 必须在你指定的物理真机上复测，以该机数据为准。
- 关闭省电模式；固定亮度/音量；记录环境温度和起始电量。
- 每轮测试前冷启动；每轮至少 3 次，取中位数；报告全部分布，不只报最好一次。
- 录屏使用设备原生 60 fps 录制或采集卡。
- 帧率门槛只认 **Release APK + 游戏内 CSV**；Unity Profiler 只连 Development Build 做逐系统拆解，不能把 Dev 数据当成最终帧率。
- 测试场景固定：出生后直走到压力测试台，不交由玩家自由发挥。

### 7.2 必测场景

| 场景 | 内容 | 记录 |
|---|---|---|
| P0 | 空场景/只跑图 | 基线帧时间、draw call |
| P1 | 8 向靶 + 双指移动射击 | 输入响应、帧时间 |
| P2 | 炸穿 + 3 连桶 + 10 秒 | 链爆尖刺、碎片数、物理耗时 |
| P3 | 高台坍塌 + 压死 + 碎片 | 坍塌块数、碰撞重建耗时 |
| P4 | 200 可见碎片 + 12 坍塌块 + 3 连爆 | 同屏碎片、平均/1% low、最大帧、GC |
| P5 | 200 全 Rigidbody2D 实验 | 真实全刚体上限、失败点 |
| P6 | 10 分钟循环热稳定 | 热降频后平均/1% low、崩溃 |

### 7.3 M1 性能门槛

在基线真机、1080p、世界低分辨率渲染下：

- **P4 压力场景：平均 ≥ 59 fps，1% low ≥ 54 fps，无单帧 > 33 ms。**
- **正常跑图：平均 ≥ 59.5 fps，1% low ≥ 56 fps。**
- **10 分钟热稳定：平均 ≥ 57 fps，1% low ≥ 50 fps，无崩溃。**
- 同屏可见/被模拟碎片 ≥ 200；T0 全物理坍塌块 ≤ 12；T1 小碎片/尸体 ≤ 40。
- 稳态 GC ≤ 1 KB/帧（预热后采样）。
- 主线程 p95（脚本 + 物理 + 提交 + 碎片/粒子 + GC）合计 ≤ 13.8 ms（或逐项记录并解释系统差异）。
- 构建可安装、冷启动到可操作 ≤ 5 s（M1 记录基线，不以此优化）。
- 若 P4 不达标：
  1. 先查是否 Dev Build/Profiler 开销；
  2. 降 T1 刚体数、T2 寿命、链爆粒子上限；
  3. 优化 chunk 重建与输入/UI 更新；
  4. 仍不达标，则 M1 直接记 No-Go/需改方案，**不允许隐藏真实数字**。

> 200 个全 Rigidbody 是 P5，不是 P4 的替代品。P5 失败不等于 M1 失败，但必须如实报告“纯全刚体上限约为 X 个”。该测试结果只作 M3 余量参考，不计入 Go/No-Go。
>
> **数据红线：** 没有真机就写“未采集”，不把 Editor/模拟器数字伪装成手机结果；宁可 No-Go，不允许编数。

## 8. 功能验收清单

### P0（任一失败 = M1 不能通过）

**构建与基础：**
- [ ] Debug APK 与 Release APK 均可安装、启动、进入测试关；
- [ ] 真机横屏、安全区正确，无遮挡关键触控；
- [ ] 连续游玩 10 分钟不崩溃；切后台/回前台不坏输入状态；
- [ ] 控制台无未处理异常、无每帧 GC 爆量警告。

**移动：**
- [ ] 可完成跳台路线；长按/短按跳跃高度不同；
- [ ] 土狼时间与跳跃缓冲按配置生效；
- [ ] 空中下+跳触发下压砸地；下压不穿完整混凝土；
- [ ] 跑动/下落撞墙不粘边、不穿地、不无限下滑。

**射击与瞄准：**
- [ ] 无目标弹道严格 8 向；锁定目标只在当前扇区内修正，无跨扇区/反向拐弯；
- [ ] 自动瞄准不隔墙锁敌，目标切换无明显抖动；
- [ ] 摇杆推动时优先所选扇区；摇杆空置时仍能锁近处可见敌人；
- [ ] 自动近战在 1.15 格内出现世界环 + tick 音效；出刀有 2 帧 hitstop；
- [ ] **按住/按下射击或手雷时不出现自动刀**，且射击/手雷指令不被消耗或替代；
- [ ] 1.35 格外不误触自动近战；装甲目标不触发自动近战；

## 11. 通过/不通过判定

### Go（进入 M2）

- P0 全部通过；
- 200 可见碎片压力场景达到第 7.3 节门槛（真机 Release）；
- 自动瞄准 + 自动近战在至少 2 名试玩者上无“无法操作”级别的问题；小刀在射击/手雷意图下零误触；
- 装甲目标必须由坍塌压死、反馈齐全、闸门开启；
- 两种涌现玩法均可稳定复现，且性能数据可解释；
- P5 全刚体数据已如实写入报告，但不作为 Go/No-Go 条件；
- 没有未关闭的高风险架构问题。

### Conditional Go（可进入 M2，但先修指定项）

- P0 **全部通过**，不存在被豁免的性能、触控、破坏或构建硬门槛；
- 仅 P1 有已知问题，且有明确的修复窗口与责任人；
- 自动瞄准/情境小刀只是需要继续调参，方案不需要推翻；
- 进入 M2 前先冻结 1~2 天修复 P1，不得把问题带入量产。

### No-Go（回到方案阶段）

- 200 可见碎片在目标真机上无法稳定 60 fps，且降级后仍不达标；
- 自动瞄准+三键无法在真机上稳定操作，需要改成右摇杆/第四键等结构改动；
- 支撑坍塌无法在预算内做成可读、可控的玩法；
- 环境或真机问题导致整个 M1 无法完成实测。

> 性能、三键操作、两种涌现玩法、APK 真机运行属于不可用 Conditional Go 豁免的 P0；M1 不通过就是回到方案阶段，不把核心风险带进 M2。
