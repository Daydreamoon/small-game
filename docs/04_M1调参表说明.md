# M1 调参表说明（给不看代码的人）

> 位置：`UnityProject/Assets/Resources/Config/*.csv`
> 状态：首版基线，尚未经过 Unity 编译/真机验证；数值会按 M1 实测修改。
> 目标：你能只改 CSV、重新构建/重载，就判断手感变化；不需要碰脚本。

---

## 1. 先看这里

每张表都是同一套列：

| 列 | 含义 |
|---|---|
| `key` | 运行时参数名；不要改键名 |
| `value` | 当前数值 |
| `unit` | 单位（u/s、格、px、s、帧、hp 等） |
| `min` / `max` | 合法范围；超出会被导入器拒绝/夹紧 |
| `tune_up` | **把这个值调大，玩家会感觉什么** |
| `tune_down` | **把这个值调小，玩家会感觉什么** |

调参流程：

1. 改 CSV 的 `value`（保留其它列）；
2. 重新导入/重新构建，或在开发包启动时读取 `Application.persistentDataPath/M1TuningOverride.csv`（两列 `key,value`）覆盖；
3. 写入调参记录：旧值 → 新值 → 玩家体感变化；
4. 若改到 `min/max` 之外，先修正范围，再测。

M1 的自动近战有一个**硬门禁不是参数**：只要 Fire/Grenade 任一按住或刚按下，就不允许自动出刀。可以调 `meleeRange` / `meleeDwell` / `meleeCooldown`，但不能通过调参绕过“射击/手雷意图下零误触”这个 P0 条件。

## 2. 每张表一句话

| CSV | 一句话 | 主要影响 |
|---|---|---|
| `player.csv` | 角色“身体”的全部手感：跑、跳、土狼、缓冲、下压、生命。 | 移动、跳跃、砸地、容错 |
| `combat.csv` | 8 向射击、自动瞄准、三连、小刀、手雷的全部战斗节奏。 | 命中、爆发、拆地形、近战 |
| `explosion.csv` | 油桶/弹药箱的伤害与链爆节奏。 | 连锁爽感、尖刺、拆地形 |
| `feel.csv` | 顿帧、震屏四档、Boss/通关慢镜头的演出尺度。 | 打击感、镜头、慢镜头 |
| `camera.csv` | 跟随的 lookahead / 死区 / 阻尼 / 像素吸附。 | 镜头跟随、抖动、可读性 |
| `debris.csv` | 同屏碎片预算、T0/T1/T2 寿命与尺寸、性能采样窗口。 | 爽感、性能、M3 余量 |
| `terrain.csv` | 瓦片材质耐久、分块数量、坍塌预警与碰撞预算。 | 挖地形、坍塌、CPU 稳定 |
| `enemies.csv` | 木靶/巡逻假人的 HP、速度、接触伤害。 | 训练靶与压力验证 |

## 3. 每张表的调参重点

### 3.1 `player.csv`

- 感觉“跳不上去”：先看 `jumpVelocity`、`gravityRise`、`gravityFall`，再调平台间距，不要只加大跳。
- 感觉“起步肉/停不住”：调 `groundAccel`、`groundDecel`，再动 `runSpeed`。
- 感觉“空中修正太强/太硬”：调 `airAccel`；不要为了容错把空中速度加到比地面还高。
- 感觉“手机容错差”：优先 `coyoteTime`、`jumpBuffer`，而不是加自动跳。
- 感觉“下压砸地没重量”：调 `slamAccel`、`slamMaxSpeed`、`slamRadius` 和对应的震屏（`feel.csv`）。
- 不要用 `playerWidth` / `playerHeight` 修手感；它们改变碰撞体，会让关卡路线/卡位全部重测。

### 3.2 `combat.csv`

- 射击手感先调 `rifleShotInterval`、`rifleBurstCooldown`、`rifleRecoil`，再调伤害。
- 自动瞄准太“抢”：先降 `aimAssistHalfAngle`，再调 `targetHysteresis`；不要先加右摇杆。
- 自动瞄准看不见/锁不到：先确认 `maxTargetRange` 和视线判定，再放宽容差。
- `meleeRange`：调大 = 更早出刀，更安全但更可能替玩家“决定”近身时机；调小 = 必须贴脸。
- `meleeDwell`：调大 = 进入半径后更久才出刀，更像有预警；调小 = 立即出刀，更突然。
- `meleeHitstopFrames`：2 帧是 P0 的默认；不要靠调到 5 帧来掩盖判断问题。
- 手雷：`grenadeContactFuse` / `grenadeMaxFuse` 决定“落地立刻炸”还是“能再滚一下”；`grenadeTerrainRadius` 决定拆地形效率。
- **自动近战在 Fire/Grenade 意图下永不触发是代码约束，任何 CSV 调整都不应该改变它。**

### 3.3 `explosion.csv`

- 链爆“没感觉”：先看 `chainDelayMin/Max`，再加大 `barrelRadius` / `crateRadius`。
- 链爆“卡一下”：降 `chainPerFrame`、`chainMax`，并看粒子/碎片是否同时爆量。
- 爆炸“拆地形太快”或“拆不动”：调 `barrelTerrainDamage` / `crateTerrainDamage` 与目标材质 HP（`terrain.csv`）。
- 不要用无限提高 `chainMax` 来制造爽感；屏幕震动和帧时间都会被拖垮。

### 3.4 `feel.csv`

- 普通击杀：2~3 帧 hitstop + 1 px 震屏；不要用慢镜头。
- 爆炸震屏低于普通击杀，意味着“爆炸比小兵死亡还轻”，不合格。
- Boss 慢镜头：只在 `BossDeath` 调试/正式白名单事件；参数范围 0.5~0.8 s。
- 通关慢镜：只在 `LevelClear`；不要和 Boss 死亡叠加。
- `hitstopCooldown` 调大 = 连杀更顺滑但反馈少；调小 = 多杀更容易顿帧卡住。M1 真机要重点摸这一项。

### 3.5 `camera.csv`

- `lookaheadX/Y` 调大 = 镜头提前看前方，预判更好，但角色会偏屏；调小 = 更居中。
- `damping` 调大 = 跟随更软；调小 = 更硬更及时。
- 像素吸附固定为 1/16 格（1 个美术像素）；不要改成更细，否则画面会抖。

### 3.6 `debris.csv`

- `visualTarget` 是“同屏可见/被模拟碎片”的目标，不是 T0/T1 刚体数量。
- `fullBodyMax` 是全物理小碎片上限；M1 P4 门槛不要求填满它。
- 200 个全 Rigidbody 是单独的 P5 实验；它不计 Go/No-Go，只用于写 M3 优化余量。
- `t2LifetimeMin/Max` 调大可增加“满屏碎屑”的爽感，但会更快吃掉 T2 池。
- 真机采集窗口由 `perfWindowSeconds` 决定；报告必须写清窗口。

### 3.7 `terrain.csv`

- `dirtHP` / `concreteHP` / `supportHP`：调大 = 枪/爆炸更难拆，节奏更慢；调小 = 更容易“改写地图”，但也更容易误拆路线。
- `supportDelay`：调大 = 坍塌预警更明显、更戏剧化；调小 = 更突然，玩家更容易被砸。
- `colliderBudget`：调大 = 碰撞更及时但 CPU 峰值高；调小 = 可能晚一帧。
- 分块尺寸 M1 默认 16；不要在没有真机数据的情况下改。

### 3.8 `enemies.csv`

- 木靶 HP 用于瞄准/伤害验证，建议保持一发三连能杀，避免训练场拖沓。
- 巡逻假人速度/接触伤害用于基本压力和物理喜剧验证，不是正式 AI。
- 装甲目标实际由代码限定为只能被坍塌击杀；改 HP 不改变这一点。

## 4. 必须和 P0 一起验收的调参项

| 调参项 | 验收观察 |
|---|---|
| 移动、跳跃、下压 | 真机连续跑跳 60 s 不卡住；短按/长按高度不同 |
| 8 向 / 自动瞄准 | 无目标弹道严格 8 向；锁定只在当前扇区内修正 |
| 自动近战 | 环 + tick + 2 帧顿帧；按住射击/手雷时绝不触发 |
| 链爆 | 顺序可读、每个物体只爆一次、单帧不尖刺 |
| 坍塌压敌 | 装甲目标只被压死；顿帧 + 震屏 + 被埋反馈齐全 |
| 200 可见碎片 | P4 真机 Release 达到门槛，且 CSV 原始数据完整 |
| 200 全刚体 | 只记录上限，不作为 Go/No-Go |

> 以上数值目前只是 M1 首版基线。**尚未编译、尚未真机实测的数值，不得当成已验收结果。**
